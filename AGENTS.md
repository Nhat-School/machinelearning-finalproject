# Project constraints

- Keep new code, downloaded data, virtual environments, model weights, caches, reports and temporary files inside this Project directory. Leave the course slides in the parent directory unchanged.
- Do not install packages globally, use Homebrew to install project dependencies, or modify shell startup files. Reuse the existing Codex document runtime read-only when practical. Install any future ML dependencies only in Project/.venv with caches set by env.sh.
- Every reported result and evidence image must come from an actual run and have a rerunnable script. Embed evidence figures in the DOCX report; include commands, source provenance and relevant numerical outputs. Never fabricate training results or screenshots.
- Keep data preparation separate from model training. Preserve raw source files, record filtering decisions and use fixed source revisions and hashes.
- The full rerun command from machine is bash Project/reproduce.sh --train. Without --train it regenerates plots, Chrome screenshots and the full DOCX from saved experiment results. Start the user app with bash Project/start_app.sh. Verify files with python3 Project/scripts/verify_evidence.py.
- The main report is reports/bao_cao_do_an_hoc_may.docx, with at least 10 pages, comparisons of requested metrics, error analysis and actual app screenshots. The older preparation-only report is supplementary.
- Append fine-tuning experiments to the same main DOCX through append_finetuning_report.py. Keep every scout result, including poor runs. Fine-tuning rerun is bash Project/reproduce.sh --finetune; preserve original baseline results.
- The Kaggle notebook is kaggle/urgency_minilm_training.ipynb. It defaults to actual training; local notebook validation explicitly reuses completed training artifacts. Never claim the notebook has been executed on Kaggle unless it actually has.
- When adding training, save split IDs, random seeds, configuration, package versions, metrics, predictions and errors. Reuse the same splits for comparisons and fit learned preprocessing only on training folds.
- Blending uses source OOF predictions to choose weight and threshold before reading test predictions. Keep reports/ensembles separate from fine_tuning and kaggle_run; Mac blend scores must not be presented as measured Kaggle blend scores. The short optimize_existing_models.ipynb reuses old outputs and never trains an encoder.

- Canonical datasets live in Datasets/UPenn, Datasets/Stanford and Datasets/CustomForum. Legacy data/raw and data/processed files are relative symlinks; preserve originals and historical test membership. Never present synthetic drafts as real records or approved gold labels.
- Reliability extension: train_reliable_deberta.py fits a joint encoder on fit partitions only, calibrates on separate calibration partitions and chooses policies on validation. Historical tests have already been inspected. Report every test row in binary metrics and separately report review coverage and automatic errors. Do not present selective accuracy as overall accuracy.
- CustomForum drafts are excluded unless a named human has approved adjudicated training labels. Keep paired scenario groups in the same split. The real-only and reviewed-custom runs stay separate.
- User-authorized exception for the final MiniLM trial: the user requested testing the three-dataset path and then instructed "continue" after the draft-label clarification. Test custom_ce/custom_pairwise as explicitly synthetic weak-supervision ablations, isolated from real-only controls. This authorizes experimental training, not human label adjudication. Keep reviewed_labels.csv pending; never call these labels human approved, independent gold, or proof of real-world accuracy. Record the task authorization and its interpretation in reports/final_minilm_trial/synthetic_authorization.json.
- Rebuild the same DOCX using append_reliability_report.py. The self-contained Kaggle reliability notebook is kaggle/reliable_deberta_training.ipynb. Local validation reuses actual completed training and must not be described as a Kaggle GPU run.

- Joint MiniLM two-source and synthetic three-source trials are complete, with five runs and two confirmation seeds. Preserve every failed and successful result in reports/final_minilm_trial. Final prototype is real_only seed42, selected after evaluation; product_selection.json records why custom was not promoted despite passing the predeclared validation rule. Do not call it universally best or fresh external validation.
- The official concise report is built by build_official_report.py through build_complete_report.py, targeting 15–18 pages and all required comparison metrics. Keep old longer reports as backups; do not re-append every historical chapter to the final DOCX. Teacher-facing final notebook is kaggle/final_best_model.ipynb, training only the two real sources; final_minilm_trial.ipynb is the full comparison notebook. Both keep synthetic labels clearly distinguished from approved labels.
